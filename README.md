# 한림해운 여수 운항정보 수집

[한림해운_운항정보.ipynb](한림해운_운항정보.ipynb)를 위에서부터 실행합니다. 구현 코드가 포함된 독립 실행 노트북이며, 브라우저 자동화를 사용하지 않습니다.

```bash
python3 -m venv /workspace/ship-venv
/workspace/ship-venv/bin/python -m pip install -r requirements.txt
/workspace/ship-venv/bin/python -m pytest -q
```

노트북의 커널로 `/workspace/ship-venv/bin/python`을 선택하세요. 로컬 PC에서는 원하는 경로에 가상환경을 만들면 됩니다. 의존성은 Python 3.12에서 검증했습니다.

노트북은 실제 목록, 키워드 대상의 상세 수집 결과, 항차별 DataFrame, 실패·보류 목록을 차례로 출력합니다. 첫 페이지 최대 30개를 조회하며 제목에 지정 키워드가 있는 게시글의 상세만 POST로 가져옵니다. 상세 본문 없이 제목만으로 항차를 생성하지 않습니다.

`ship_notice.py`는 테스트 및 유지보수용 동일 구현입니다. 수정 후 `python build_notebook.py`를 실행하면 노트북을 다시 생성합니다. 이 명령은 노트북의 기존 출력과 편집 내용을 교체하므로 필요한 결과는 먼저 보존하세요.

## 실제 사이트에서 확인한 문제와 처리

- `Chrome` User-Agent를 지정한 HTTP 요청에서 정상 응답을 받았습니다. HTTPS 주소는 404 응답이므로 원래 HTTP 주소를 사용합니다. 환경 허용 도메인 설정도 변경한 상태여서 초기 403 해소를 User-Agent 하나의 효과로 단정하지 않습니다.
- 잘못된 `<tr="">` 태그가 있으므로 `tr`만 찾으면 글을 놓칩니다. 제목 링크의 인접 셀에서 날짜와 숨김 식별자를 읽습니다.
- 상세 HTML에 `lblContent` ID가 중복·중첩되어 있습니다. 날짜 하나를 담은 작은 span 대신 바깥 본문 컨트롤을 사용합니다.
- 게시글마다 목록을 새로 받아 숨김 폼 필드와 현재 행의 `__EVENTTARGET`을 전송합니다. 실패 시 목록 재반환, 제목 불일치, 서버 오류, 본문 식별 실패를 구분합니다.
- `신기 17:00 / 여천 17:30까지 정상 운항. 이후 ... 통제`에서는 정상운항 구간을 제외합니다. 양쪽 항구의 시각은 각각 출발 항차입니다.
- 추석 시간표는 출항 헤더로 항로와 방향을 확인합니다. 요일이 포함된 9/24~9/26 범위도 세 날짜로 확장합니다.

## 결과와 재실행

기본 실행 디렉터리의 `data/` 아래에 다음 파일을 생성합니다.

| 파일 | 용도 |
| --- | --- |
| `notices.sqlite3` | 게시글 처리 이력, 본문, 항차의 원본 저장소 |
| `listing.csv` | 이번 첫 페이지 목록 |
| `audit.csv` | 누적 수집·추출 상태 및 실패 원인 |
| `voyages.csv` | 누적 항차, 필수 8개 열 우선 배치 |
| `validation_summary.json` | 이번 첫 페이지 대상 수집·분석 요약 |
| `debug/*.html` | 실제 전체 응답 HTML, 폼 상태가 포함될 수 있어 버전 관리 제외 |
| `monitor_errors.log` | 반복 감시 중 목록 수집 등의 오류 |

성공한 게시글은 재실행 시 다시 수집하지 않습니다. 본문수집실패만 명시적인 재시도로 최대 3회 처리합니다. 파서를 개선한 후에는 노트북의 선택적 **저장된 본문 재분석** 셀을 실행하면 됩니다. SQLite 저장은 게시글 단위 트랜잭션이고, CSV는 DB에서 임시 파일을 거쳐 다시 생성해 중복 추가를 방지합니다.

30분 감시는 `START_MONITOR = True`로 바꾸고 해당 셀을 실행할 때만 시작합니다. `pipeline.stop()`으로 중지할 수 있습니다. 진행 중인 HTTP 요청은 완료/타임아웃까지 기다릴 수 있습니다. 커널을 종료하면 감시도 종료되며 이력은 SQLite에 남습니다. 실제 30분간 대기하는 장기 감시는 수행하지 않았고, 시작·중지와 중복 방지 동작을 테스트했습니다.

## 검토가 필요한 결과

확인되지 않은 도착시각은 `None`입니다. 전면통제는 본문을 보존하고 `전면통제_보류`로 분류하며 항차를 만들지 않습니다. 연도 생략·상대 날짜 추론에는 별도 플래그와 근거를 기록합니다. 제목과 본문 날짜가 다르면 본문 날짜를 우선하되 `부분추출`로 표시합니다. 확정 행만 쓰려면 `추출상태 == '추출성공'`으로 필터링하세요.

정규표현식은 날짜·시각 등의 토큰을 읽고, 해석은 표 헤더·문단·변경 전후·정상/통제 구간의 관계를 사용합니다. 범용 자연어 모델이나 OCR은 포함하지 않습니다. 이미지, 복수 항로, 불분명한 날짜·출발지 등은 실패 또는 부분추출로 남겨 수동 확인이 필요합니다. 알려지지 않은 시간표를 만들어 보완하지 않습니다.

사이트 숨김 식별자를 불투명 키로 사용합니다. 해당 키가 없는 다른 형태에서는 제목+게시일 지문을 사용하며 중복 키는 오류로 처리합니다. 이미 처리한 글의 수정 감지, 페이지 전체 백필, 여러 프로세스의 동시 감시는 범위 밖입니다. 감시 사이 30개보다 많은 신규 글이 올라오면 첫 페이지 밖 게시글은 놓칠 수 있습니다.

검증 결과와 CSV 사본은 `validation/`에 제공합니다. 회귀 테스트용 실제 공개 본문은 `tests/fixtures/`에 있으며, 실제 실행 결과 생성에 사용하지 않습니다. 원래 요청서에서 언급한 이전 노트북은 제공되지 않아 그 파일 자체를 재현·수정한 것은 아닙니다.
